# Контекст для AI

Краткая фиксация текущего состояния проекта и следующего шага. Обновлять при значимых изменениях.

---

## Текущее состояние

**Проект**: маркетплейс (Ozon-like), монорепо: Go-сервисы + Next.js + Expo (mobile). Репозиторий: `https://github.com/alexevil1979/ozon.git`, remote `ozon`. Каталог на VPS для тестов: `/ssd/www/ozon`, домен: `ozon.1tlt.ru`.

**Реализовано:**

- **Бэкенд (Go, Echo, pgx)**  
  Auth (:8080), User (:8081), Catalog (:8082), Search (:8083), Seller (:8084), Order (:8085), Admin (:8086). PostgreSQL, Redis, OpenSearch, MinIO — через `infra/docker-compose.yml`. JWT, миграции при старте, CORS в Catalog и Search.

- **Веб (Next.js 15, App Router)**  
  Покупатель: главная, каталог с фильтрами, карточка товара, корзина (cookie), оформление заказа, «Мои заказы», оплата (заглушка). Продавец: вход, дашборд, CRUD товаров. Админ: вход по ключу, пользователи, модерация товаров (draft/active). API-маршруты проксируют к Go-сервисам.

- **Мобильное приложение (Expo, apps/mobile)**  
  Один файл `App.js`: экраны каталог, товар, корзина, заказы, логин. Запросы к Auth, Catalog, Order по localhost/IP. Корзина и токен в памяти (без персистентности).

- **Инфраструктура и доки**  
  K8s: Deployment + Service для всех семи Go-сервисов в `infra/k8s/`. Observability: Prometheus + Grafana в docker-compose (профиль `observability`). Документация установки: `docs/DEPLOY-VPS.md` (Nginx), `docs/DEPLOY-VPS-APACHE.md` (Apache).

- **Прочее**  
  Vitest в `apps/web` (тест `lib/utils.test.ts`). Общее правило: после изменений самостоятельно коммитить и пушить в git (`.cursor/rules/git-push-after-changes.mdc`).

**Что остаётся заглушкой или не сделано:** реальная оплата (сейчас `stub_<id>`), персистентность токена/корзины в мобильном приложении, E2E-тесты, CI/CD, метрики Go-сервисов для Prometheus.

## Следующий шаг

**Рекомендуемый следующий шаг:** интеграция реальной оплаты (один провайдер: ЮKassa, Stripe, Robokassa и т.п.) — эндпоинт в Order service или отдельный payment-webhook, обновление статуса заказа после callback, обновление кнопки «Оплатить» и страницы заказа в вебе.

**Альтернативы (по приоритету):**

1. Мобильное приложение: сохранять JWT и корзину в AsyncStorage, при необходимости — Expo Router и отдельные экраны.
2. CI/CD: GitHub Actions (lint, test, build) и при необходимости деплой на VPS.
3. E2E: Playwright или Cypress для сценариев покупатель (каталог → корзина → заказ).

При получении новой задачи от пользователя — выполнить её и обновить этот файл (текущее состояние + следующий шаг).
